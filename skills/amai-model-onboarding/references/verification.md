## 先检查测试副作用

运行前读目标包 TestMain、初始化和请求。不要直接 `go test ./...`：当前 `internal/pkg/llm/main_test.go` 加载 local 配置/数据库，`internal/logic/video/main_test.go` 还初始化 Redis/OSS/队列；部分 provider 测试是真实调用示例。指定 -run 也会执行 TestMain。

- Go：gofmt 后遵守适用项目检查。当前父目录 `CLAUDE.md` 要求修改 Go 后依次执行 `go build ./...`、`go vet ./...`、涉及范围的 `go test`；build/vet 不等于全量执行测试。相关测试仍须先检查副作用。规则变化时按当前要求核对，不擅自缩减必需检查。
- YAML：参考 `internal/config/config_load_test.go::TestLoadConfigFiles` 使用真实 go-zero 加载器，静态脚本不替代加载器。
- 参数：文档、语言 JSON、请求类型、后端校验、provider 字段及计费默认一致；覆盖 @ 的开关/例外、最终 prompt 和素材顺序，以及普通/画布列表在目标语言下的实际返回。模拟覆盖新增行为，不为所有历史模型补测试。
- 价格：从 client 生成实际 conf_id，检查每个有效组合唯一价格源、公式边界、数量和取整；图片/视频比较预估与创建，文本比较 usage 与结算。
- DB：库身份、业务键、目标字段差异、影响行数、回读。只读查询现状不能证明拟写入值已经生效。

离线候选：`internal/types/cost_config_test.go`、`internal/logic/common/model_client_test.go`、`internal/pkg/chat/extended_message_test.go`、`internal/pkg/llm/gptimage/qiniu/image_test.go`、`internal/pkg/llm/gptimage/refimage/refimage_test.go`、`internal/types/video_test.go`。按改动选用，并复查初始化。

## 真实调用预算

只有实际接入/真实自测请求才应用默认预算；编写 Skill、静态评估、演练不触发费用。

1. 记录模型、接入任务、供应商、测试账号、采购报价/有效期、币种、明确汇率、剩余额度。采购成本、平台售价、用户积分分别记录；dev 余额不代表供应商费用。
2. 选择覆盖新增能力的最小有效用例，调用前计算可解释的费用上界：文本含输入和最大输出/推理 token，图片含质量/尺寸/张数/参考图，视频含时长/分辨率/音频/参考素材/最低收费。公式或汇率不明先询问，不以平均费用冒充上界。
3. 用人民币小数精确累计：`已结算费用 + 未结算请求预留上界 + 本次预留上界 <= 已授权上限`。同一逻辑模型的别名/client、失败、重试共享预算；多模型分别记账，不挪用另一模型额度；续跑读取原账本。
4. 实测前检查 SDK 重试、队列重试、候选切换、批量和并发。优先隔离测试入口，限定候选、次数、并发和生成量；不能保证总费用边界时先不触发，说明限制并询问具体预算/运行方式。不直接改共享 dev 路由影响其他用户。
5. 每次可能收费的提交都先预留再记录。超时/响应丢失不等于未收费，未确认退款/零收费就保留预留，不盲目重提。usage × 报价可以形成核算值，但不是实际扣款证据；取得供应商账单/消费明细或等价的可信扣款记录后，才能更新已结算成本。只有估值就标估计/预留，不能写实付或释放未确认费用。
6. 异步任务记录 TaskID 和原 client，轮询不重复生成。设置有依据的超时和有限轮询，查询若收费同样计入。超时仍运行则标结果未定并保留预算。
7. 预计超限则暂停付费调用，汇总结果和剩余用例再询问，继续离线检查和文档。追加预算更新本任务上限，不重置累计。

凭证使用既有安全注入渠道，核对模型调用权限；缺凭证/额度只阻塞真实调用，不主动充值/开通，不将秘密写入命令输出或文档。

## 真实证据与完成状态

| 模态 | 最小实际验证 | 证据 |
|---|---|---|
| 文本 | 指定供应商、SSE 正常结束、usage 与本次计费可核对 | 非敏感参数、事件摘要、usage、结算结果 |
| 图片 | 主要生成/参考图能力、结果可读、参数实际透传 | client/别名、参数、任务终态、资产/结果、费用 |
| 视频 | TaskID、原 client 轮询至终态、结果可读 | 提交/查询、状态轨迹、参数、结果、费用 |

有本地或既有 dev 后端时验证模型列表、报价/创建/查询和扣费。启动前确认不会消费无关队列、运行 cron、发送通知，优先受控进程或隔离账户。第一版不部署共享服务，旧二进制不会自动加载本地代码/YAML。

只直接调用 provider，只能证明上游适配，平台任务/计费另记未实测。前端移交可通过后端返回和模拟事件验证，无需界面。

每例记计划、已执行通过、已执行失败、阻塞、未执行之一及证据位置。离线通过不代替真实通过，DB 回读不代替可调用，上游成功不代替资产/扣费正确。不自动提交、推送、合并或部署。

## 供应商对账：接入完成门槛

本轮用户明确要求：平台成本、用户扣费、供应商用量和实际扣款必须核对，接入才算完成。不能将“开发可先交付、对账仅是后续待办”作为整体完成标准。可报告代码已完成，但整体仍为部分完成/待对账。

| 核对项 | 证据来源 | 不能替代它的内容 |
|---|---|---|
| 平台成本记录 | 任务/结算记录中的 cost_credits、original_cost_credits 或对应字段，连同估算公式、单价、渠道折扣 | 文档里的示例成本或供应商 usage |
| 用户实际扣费 | 本次任务关联的积分流水/余额变动，含免费、优惠、失败退还等实际情况 | 只有报价接口或任务计划扣费字段 |
| 供应商返回用量 | 原始响应/任务保存的 usage_detail、total_tokens 或该计费模式实际提供的计量数据 | 本地预估 token/时长 |
| 供应商实际采购扣款 | 供应商后台消费明细、账单、可信费用 API 或人工提供的对应扣款证据 | usage × 单价、截图 alt、未实际读取的附件、笼统“已跑通” |

按请求/尝试建立匹配关系：环境、逻辑模型、client/上游型号、时间及其时区、MsgOID、参数和结果；供应商提供 request/task ID 时一并保留。一次平台请求可能对应多次计费尝试，需覆盖重试、备用渠道和仍未结算的尝试，不能只核对最终成功那一次。

没有稳定上游 request ID 时，用其他足够区分请求的证据组合或人工确认关联；不能宣称 MsgOID 能直接在供应商后台查到。多条候选无法消歧时继续标待对账，并明确需要哪条记录。无后台访问能力时请求具体明细或由人工核对，不自动扩大权限、抓取无关账单或另开付费请求。

“核对通过”不是要求平台售价等于采购成本、预估用量等于上游 usage，而是：四项有对应证据、币种/单位与换算明确、全部可能收费的尝试有归属，差异能用已确认的商业规则和计费实现解释；非预期差异已修复并重验或由用户明确裁决。不能为了让数值相等擅自改价、补流水或按 usage 重算已扣费用。

若供应商按张/秒等模式不返回 token usage，应核查它实际提供的计量数据及计费依据，不能编造 token。费用仍未结算、证据缺失或非预期差异未处理时，标“未完成／待对账”。不凭生成成功或估值低于预算将其关闭。

GPT Image 当前属于前置估算，返回 usage 被保存但未因此重算本次扣费；详见[图片案例](cases/gpt-image-2.5.md)。不能将这条模式泛化为全部文本/视频计费。

## 业务 Skill／专家团移交

流程第 10 项指业务侧服务，不是 Codex Skill 自身。本版生成资料即可；不发消息、不改该服务配置，不将它已接收/已上线列为事实。

移交资料至少包含：环境及实际状态、ModelID/逻辑名/各供应商别名、支持能力与请求参数、@/画布/语言说明、接口和开发文档位置、价格及对账结论、尚需对方配置的模型绑定项、已知限制。配置入口/负责人不明就标待确认，不猜接口或接收者。

仓库 `internal/config/skill.go`、`internal/pkg/skill/list2.go`、`internal/logic/skill/skilllistlogic.go` 能证明业务 Skill 的模型列表有独立来源，不能证明仅改本服务 YAML 就已同步。后续人工上线与通知保留为移交待办，不扩大本版范围。

## 人工案例迭代

使用 [接入记录](../assets/case-record.md) 保存最小事实。用户可只提供 diff、文档、步骤或错误；优先在授权环境补证据，不要求填写完整模板，不扩大到无关文档/业务数据。

1. 先确认是复盘/更新，不重新执行接入；读取人工步骤、最终差异及结果。
2. 区分需求/价格未定、供应商差异、工具限制、实现错误、Skill 指引错误；保留人工修正前后差异和成功条件。
3. 只沉淀会改变下次决策的知识。稳定项目规则入主流程，供应商/模型特例入对应分支，单例不推广为三模态通则。
4. 按具体步骤、渠道和参数组合注明证据、范围、验证层级。用户确认人工跑通可记相应步骤的人工验证；未提供的对账细节仍记未知，不虚构日志或采购扣款，不将单渠道成功扩为整例成功。
5. 用户要求迭代时更新造成偏差的最小段落，删除失效指导；验证 Skill/相关脚本，以原案例重验，共用规则变化再补另一分支案例。不重复请求已有修改授权。
6. 没有真实案例前不建空案例库；有复用价值时脱敏后添加案例参考，从对应模态链接。

辅助脚本变更后运行 `python3 <skill-dir>/tests/test_helpers.py`。这些离线回归覆盖元数据/画布浅覆盖/@ 白名单与错误输出，不证明实际模型调用、供应商对账或整套接入已完成。另用独立场景核对完成门槛、预算与移交边界，不能以匹配文案的测试代替行为检查。

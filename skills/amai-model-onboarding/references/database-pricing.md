# 模型参数与价格配置

在用户已要求接入或更新模型时使用本流程，覆盖 `llm_model`、`cost_config` 及其代码映射。
默认目标是 dev；用户明确指定的环境优先。不得把 dev 的授权扩大到 test 或 prod。
创建、评估或修改本 Skill 本身不等于授权修改业务数据库。
本流程截止后端开发交付；不因配置需要而自行合并、部署或开展前后端联调。
人工流程与失效条目的解释见 [人工接入检查表](manual-onboarding-checklist.md)；样例用于定位检查点，不替代本次证据。

## 先定位环境和现状

1. 发现目标环境的 MySQL MCP 工具，阅读当前工具声明，区分只读查询与写入能力。
2. 用 `SELECT DATABASE()` 核实实际库名；不匹配时先查明环境映射，不继续变更。
3. 读取这两张表的实时列定义、默认值、可空性、索引及必要的事务能力信息。
4. 记录源码分支、commit、目标环境、查询时间和相关未提交改动，区分源码与运行环境证据。
5. 只查询本次目标模型及必要的同类代表配置，不导出全表或无关业务数据。

当前已知业务键如下，每次执行仍以目标库的真实索引为准：

| 表 | 业务键 | 关联意义 |
|---|---|---|
| `llm_model` | `model_id` | 对应 YAML 模型入口和请求中的 ModelID |
| `cost_config` | `model_name + conf_id` | 对应运行时模型名及 client/业务代码产生的计费规格 |

不要跨环境复制自增 `id`。同一模型在不同环境的自增 ID 可以不同。
已有核查发现环境之间存在额外字段和唯一索引差异，ORM 生成结构也可能落后于实际表结构。
不要把 `.gen.go`、旧 SQL 或同一环境的历史结构当成目标库的完整 schema。
若拟修改列不存在，先判断是否误用其他环境字段；需要 schema 变更时另列具体范围，不自动扩表。

## 建立本次变更依据

按接入规格整理 ModelID、内部模型名、展示名、模态、client/provider、有效参数和价格来源。
区分产品展示名、YAML 顶层 `model_name`、provider 实际型号及 `conf_id`，不要用名称相似代替映射。
把代码实际可能生成的计费 key 与配置行逐一对应，检查缺失、重复、停用及遗留记录。
`status=1` 只代表记录启用，不证明当前 client 会使用该价格；不能直接复制所有启用价格档。

读取并保存相关目标行的 before 快照，包含：

- 环境、表名、业务键、当前主键和 `updated_at`。
- 本次拟改字段原值、完整相关 JSON，以及用于并发校验的原值或稳定摘要。
- 行原先不存在的事实、实际唯一约束、计划插入或更新的预期数量。

快照仅保存必要配置，避开连接串、AccessKey、token 等凭据；不要从业务配置中寻找备用写连接。
形成字段级 before/after 差异和 apply/rollback 方案，明确每项修改的需求来源。
恢复方案必须区分“恢复原值”与“删除本次新建行”，不能用整表备份替代精确范围。

## 生成模型参数 JSON

`llm_model.config_detail` 是前端展示参数的重要来源，但不是完整后端校验器。
模型列表由 `internal/logic/model/listlogic.go` 遍历 YAML 模型，再按 ModelID 查库并输出 `ExtInfo`。
因此只插入 `llm_model` 不会自动注册模型；必须同时检查 YAML 模型入口和 client 路由。
展示名可能由 JSON 内的 `model_display_name` 覆盖 YAML，不能仅修改表顶层同名列后推断效果。

1. 从同类当前配置确认根结构、语言节点、`field_map` 和展示字段，不凭样例猜测 schema。
2. 比较文档、请求类型、后端校验、provider payload 的字段名、枚举、默认值和边界。
3. 对本次变更使用路径明确的 JSON 修改或基于最新快照的合并，保留未知字段和其他语言。
4. 核对 `zh-CN`、`en-US` 参数结构及对应枚举；文案可不同，不静默删除现存语言。
5. 校验 JSON 类型、必填字段、默认选项、数值范围、素材数量及互斥/依赖关系。

有画布入口时检查本地化后的 `canvas_show` 为 JSON 布尔值 `true`，不是字符串 `"true"` 或数字 `1`。
当前列表仅在请求 `canvas_show=true` 时过滤；字段缺失、类型不对或值为 false 都不会出现在该画布列表中。
分别核对各语言输出，防止语言浅覆盖改变画布可见性；普通列表和画布列表不能互相代替验证。
`internal/pkg/i18n/config_detail.go` 对语言节点做浅层覆盖，并移除语言根节点后返回。
不要假设缺失的语言字段会从另一语言深度合并；特别检查 `field_map` 整体被覆盖的结果。
DB 的 UI 默认值不会自动注入请求或 provider，缺参行为必须与后端实际默认值一起核对。
前端已有组件不能表达的新字段或交互应写入交付文档，不擅自以数据库配置宣称前端已支持。

## 定价依据、单位与计费来源

分别确认供应商成本、平台售价、计价单位、币种/换算依据、折扣与有效条件。
采购报价先有商务确认来源，再由开发核对供应商、具体模型、计费项目、折扣、有效期与实际接入账户。
开发复核是核证已有商业结论与实现是否一致；已有明确证据时直接记录，不机械地再让用户确认一次。
来源未提供、过期或与供应商当前报价/账户政策冲突时集中提出差异，不能擅自换用另一渠道报价。
用户已明确的售价和规则直接采用；文档中冲突报价、截图旧价或未确认商业规则不能自行裁决。
价格缺失或冲突时提出具体问题，同时继续不依赖该价格的文档与后端开发。
未知价格保持待定，不写成 0、不启用该模型的收费入口，也不借用相近型号价格补齐。
已知按 token 模型的顶层价格为 0 可能是正常结构，须检查真正读取的 JSON 价格后判断。

当前项目的成本/金额字段以分为基础，销售积分的展示换算为 `10 积分 = 1 米粒`。
文本和相关图片模型 JSON 的 token 单价为每百万 token；不要把元、分、积分或米粒混写。
检查目标列的 decimal/int 精度以及代码的取整顺序，不从 `profit_rate` 自动反推用户售价。
`charge_unit`、备注或 YAML `cost_type` 不能单独证明计费方式，实际消费代码优先。

| 模态 | 必须核对的真实来源 | 进一步参考 |
|---|---|---|
| 文本 | `common/chat.go` 的 `ChatTotalCredits`、`types/cost_config.go` 的 `CalcPrice`；当前以 YAML ModelName 同时匹配 `model_name` 和 `conf_id` | [文本接入](backend-text.md) |
| 图片 | client 的 `GetImageCostID`、`common/cost_config.go` 的 `IVCostConfig` 及型号专用分支；检查按次、计费基数与预估 token | [图片接入](backend-image.md) |
| 视频 | client 的 `GetVideoCostID`、`IVCostConfig`、按秒或型号专用公式；检查时长档、声音、参考素材 | [视频接入](backend-video.md) |

不要固定保存本次样例的实时价格；每次读取指定来源与目标库后生成变更。
文本价格虽有 cached/time range 结构，仍要核对调用实参；当前缓存命中分支也传 `isCached=false`。
GPT Image 的预估 token 分支按明确 ModelID 选择，并读取 `uncached.default_range`；新增 ID 要检查代码分支。
Seedance 的部分版本从 `internal/types/video.go` 的价格 map 计算，修改 DB 不足以改变实际单价。
H3 等型号还会加入参考视频时长或参考图费用；型号价格规则不能统一简化成表内一个数字。
核对渠道折扣、Free 条件、生成数量/批次和取整，区分数据库配置价、成本记录和实际扣费。
前端移交文档按“官方首行、渠道随后”展示报价及来源，实际落库采用已确认的采购与销售规则，二者不能混为同一依据。
可复用已有 `amai-toc-price-sql` 的单位与计费入口知识；不要调用其整套线上查询工作流来执行本次调价。

## 按当前工具能力执行

工具权限会变化；曾经只读不是永久限制，具有写入能力也不等于任意环境都获授权。
用户已授权目标环境的模型接入及配置，且当前工具可写时，完成具体 diff 后继续执行范围内变更，不重复确认。
只有目标环境、关键价格或本次写入授权确实缺失时才询问；明确指出缺少哪一项，并继续独立工作。
若工具当前仅可读，完成所有可做的读取、校验和 SQL 产物，标记实际写入尚未执行。

执行前复读目标行并比较 before 快照，处理本次准备期间出现的并发修改。
使用业务键和确认后的行身份定位，更新仅涉及的列/JSON 路径；不要无条件覆盖整行。
插入前检查所有唯一约束，不能盲用 `ON DUPLICATE KEY UPDATE` 把其他唯一键冲突变成更新其他行。
修改已存在行时使用旧字段值/稳定摘要条件，或在有保证的事务内锁定并复核；仅秒级时间戳不足以覆盖所有并发变化。

需要将多行或两表作为一个原子变更时，先确认工具保证事务期间使用同一连接/会话。
不能假设分开的 MCP 调用中 `START TRANSACTION`、DML、`COMMIT` 属于同一会话。
只有工具明确保证单次事务批次或有会话绑定的事务 API 时，才采用对应事务方式。
没有该保证时，不冒充原子执行；交付在受支持执行器运行的完整事务 SQL，并标明待执行状态。
任一断言失败时回滚整个已保证的事务；执行结果不明时先回读查证，不能盲目重放写入。

检查每条语句的预期目标与影响行数，结合驱动的 matched/changed rows 语义解释无变化更新。
重复执行应产生无新增差异的结果；业务键冲突、意外多行或前置值变化都应停止受影响写入并重新核对。
提交后按业务键回读，确认 JSON、价格、状态、行数与期望一致，不只依赖工具的成功提示。

## 验证、恢复与交付

模型列表当前实时读取 `llm_model`，价格路径也实时查询相关记录；不要默认增加清缓存步骤。
YAML 和 client 注册属于代码/启动配置，DB 回读成功不能证明运行中的服务已加载对应版本。
按 [验证与交付](verification.md) 完成后端范围的参数序列化、计费分支和代表请求检查；区分静态核对、测试与实际运行证据。
真实调用仍遵守每个逻辑模型、本次任务累计人民币 10 元采购成本上限；不得为了补对账证据无限重试。
每次实际测试按可关联的请求/任务标识核对四项：平台生成记录的成本、用户实际扣费、供应商 usage、供应商实际采购扣款。
供应商 usage 与采购扣款分别取证；用 usage 乘报价的估算不能替代实际账单扣款，也不能把平台售价当采购支出。
将差异定位到计价单位、规格、折扣、取整、失败重试或结算时点，并记录可解释的计算与实际金额。
四项核对是本期“接入完成”的必要条件；账单未出、后台无权访问或差异未解释时标记“部分完成/待对账”，不能仍标已完成。
完成对账不扩大到上线操作；“通知 Skill”指业务侧 Skill/专家团移交，只生成配置与验证资料，不发消息、不写另一服务。
本期不部署时，交付中注明配置生效所需的代码版本和启动配置，不将发布完成作为事实。
恢复使用 before 快照并校验当前仍是本次写入后的值，避免覆盖之后的新变更。
新建行仅在身份和当前内容均吻合时恢复为不存在；已有行只恢复本次修改字段。
涉及已被其他使用方引用的模型时，优先列出禁用或恢复原配置方案，不自动删除关联业务数据。
报告实际完成的环境、业务键、字段变化、执行/未执行状态、自测和回读结果及待定项。
不要宣称三模态已人工跑通，除非本次确有相应证据；无需为两表配置另建通用管理平台。
